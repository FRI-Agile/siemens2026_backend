# Changelog

- **2026-10-12 · schema 0.1.0** — Initial documentation: conventions, templates.
- **2026-10-13 · schema 0.1.1** — Added the `kernel` schema (host-owned) with `kernel.idempotency`: HTTP `Idempotency-Key` claims and captured responses, `idx_idempotency_expires_at` for the daily `IdempotencyPruner` (03:00 UTC), the `idempotency_completed_has_status` CHECK and churn autovacuum settings — see ADR-D001. Landed in `configs/postgres/init/01-create-db.sql`, now loaded by the AppHost — see ADR-D002.
- **2026-10-21 · schema 0.2.0** — Added the `recruitment` schema with `recruitment.job_post` (title, location, department, description, draft/published, open positions, salary, payment type, employment type, the responsible recruiter as an Entra object id) and its `recruitment.set_audit_fields()` audit trigger — see ADR-D003 and ADR-D004. Schema listed in `infra/db-schemas.txt`.
- **2026-11-02 · schema 0.3.0** — `recruitment.job_post`: `is_published BOOLEAN` replaced by `status TEXT` (`draft` / `published` / `closed`, default `draft`) with the `job_post_status_valid` CHECK, for closing and reopening a post. Applied to an existing database by hand (ADR-D005): `ALTER TABLE recruitment.job_post ADD COLUMN status TEXT NOT NULL DEFAULT 'draft' CONSTRAINT job_post_status_valid CHECK (status IN ('draft', 'published', 'closed')); UPDATE recruitment.job_post SET status = 'published' WHERE is_published; ALTER TABLE recruitment.job_post DROP COLUMN is_published;`
- **2026-11-02 · schema 0.3.1** — The `pg_trgm` extension (in `public`) and the trigram GIN indexes `idx_job_post_title` and `idx_job_post_location` behind the job post lists' search, replacing the documented no-index deviation — see ADR-D006. Applied to an existing Azure database by hand: `just azure-deploy` (allow-lists `pg_trgm` in `azure.extensions`), `just azure-db-grant` (creates the extension), then as `healthyhires_app`: `CREATE INDEX idx_job_post_title ON recruitment.job_post USING gin (title public.gin_trgm_ops); CREATE INDEX idx_job_post_location ON recruitment.job_post USING gin (location public.gin_trgm_ops);`
- **2026-11-09 · schema 0.4.0** — Candidates and their applications: `recruitment.candidate` (first and last name, a generated `display_name`, e-mail unique without case, E.164 phone), `recruitment.application` (candidate × job post, unique per pair, status `nová žiadosť` / `predvýber` / `pohovor` / `ponuka` / `prijatý` / `odmietnutý`) and `recruitment.application_document` (type `životopis` / `motivačný list` / `iné`, file metadata, upload status `nahrávanie` / `kontrola` / `overený`), each with the audit trigger. The `unaccent` extension (in `public`) and `recruitment.immutable_unaccent(text)`, with the trigram GIN indexes `idx_candidate_display_name` and `idx_candidate_email` over the unaccented text — see ADR-D007, ADR-D008 and ADR-D009 (the value sets are Slovak codes). Applied to an existing Azure database by hand: `just azure-deploy` (allow-lists `unaccent`), `just azure-db-grant` (creates it), then as `healthyhires_app` the `immutable_unaccent` function and the three tables with their indexes and triggers from `01-create-db.sql`, in that order.
- **2026-11-09 · schema 0.5.0** — Added the `files` schema with `files.file`: the metadata of every uploaded file (purpose, blob name, file name, content type, size), its lifecycle without a status column (`etag` once confirmed, `scanned_at` once ClamAV cleared it, `deleted_at` / `deleted_by` once released), the not-blank, positive-size and scanned-only-if-confirmed CHECKs, `uq_file_object_key` and the partial indexes `idx_file_pending_uploaded_at`, `idx_file_unscanned_uploaded_at` and `idx_file_deleted_at` for the scanner and the janitor — see [files](modules/files.md) and `docs/api/files/files.md`. Schema listed in `infra/db-schemas.txt`. Applied to an existing Azure database: `just azure-db-grant` (creates the schema), then as `healthyhires_app` the `files.file` table and its indexes from `01-create-db.sql`.
- **2026-11-09 · schema 0.6.0** — The transactional outbox lands: `recruitment.outbox_message` per [conventions.md § Outbox pattern](conventions.md#outbox-pattern-outbox_message), without `subject_id` and `device_id`, with the delivery-retry columns `attempts`, `next_attempt_at` and `last_error` and the `outbox_message_attempts_valid` CHECK. `recruitment.application_document` now references its file: `file_name`, `content_type`, `size_bytes` and `status` (with their CHECKs and the partial `idx_application_document_created_at`) are replaced by `file_id UUID NOT NULL` (logical → `files.file`) with the unique `uq_application_document_file_id`. Applied to an existing Azure database by hand, as `healthyhires_app` (no application_document rows exist yet): `ALTER TABLE recruitment.application_document DROP COLUMN file_name, DROP COLUMN content_type, DROP COLUMN size_bytes, DROP COLUMN status, ADD COLUMN file_id UUID NOT NULL; CREATE UNIQUE INDEX uq_application_document_file_id ON recruitment.application_document (file_id);`, then the `outbox_message` table from `01-create-db.sql`.
- **2026-11-10 · schema 0.7.0** — The public application form. `kernel.altcha_solution` (spent ALTCHA solutions, kept until their challenge expires, pruned daily by `AltchaSolutionPruner` at 03:10 UTC; ADR-022). `recruitment.candidate.phone_number` is optional (`NULL` when not given; the E.164 CHECK still applies to a value). `recruitment.application_document` gains the partial unique `uq_application_document_application_id_type` (`(application_id, type) WHERE type IN ('životopis', 'motivačný list')`): at most one CV and one cover letter per application, so the CV the AI scoring reads is one row. Applied to an existing Azure database by hand, as `healthyhires_app`: `ALTER TABLE recruitment.candidate ALTER COLUMN phone_number DROP NOT NULL; CREATE UNIQUE INDEX uq_application_document_application_id_type ON recruitment.application_document (application_id, type) WHERE type IN ('životopis', 'motivačný list');`, then the `kernel.altcha_solution` table, its index and its autovacuum settings from `01-create-db.sql`.
